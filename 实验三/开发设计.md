## UML 到代码

| 图和对象 | 所在代码 | 约束 |
| --- | --- | --- |
| `Account` | [账号服务](code/src/whale_market/accounts.py) | 注册只创建普通账号，用户名大小写无关且唯一。密码为 Argon2id 散列，随机 Cookie 在数据库中仅存摘要。会话有效期为 12 小时 |

图片内容存入 PostgreSQL `BYTEA`，上传事务和商品事务各自提交。读取范围按当前商品可见性、上传者和管理员权限判断。送审、预约和封禁等写动作从统一的 `POST /api/commands` 调用交易服务。首次管理员由命令行初始化。后续授撤权用同一个事务锁串行校验操作者、目标和管理员数量，并保存审计。

## 预约事务

1. **认证与幂等。** 入口核对会话。交易服务按账号、动作和提交标记取得事务锁，读取最终结果。回放时校验结果的当前访问权限和规范化请求摘要。同内容重试返回原记录及当前状态，修改目标或参数后的同标记请求返回冲突。
2. **锁和版本。** 新命令加锁读取商品行，再读相关预约和送审。按角色、对象、状态和版本判断能否执行。成功后保存业务、最终结果和成功审计，检查商品状态与预约及审核记录的联动。每次实际变更只递增一次商品版本。
3. **独立过期。** 写入口遇到到期的当前待确认预约时释放原事务锁，再完成独立过期事务，随后带原页面版本重新处理。服务每 5 秒扫描候选，在商品锁内核对目标。待确认截止为创建后 24 小时和约定交付时间中的较早者。
4. **结果恢复。** 技术异常回滚时可以用原标记重试。提交结果未知时以原标记查询最终结果。管理员打开他人的交付约定时须显式查询，读取与访问审计同事务完成。管理员作为交易当事人读取自己的预约时，可直接获取约定，读取仍留痕。

## 实验一待确认口径的实现选择

| 事项 | 当前口径 |
| --- | --- |
| OQ-01 字数和容量 | 去两端空白后的 Unicode 字符数。图片每张最多 5 MiB |
| OQ-02 列表稳定排序 | 发布时间降序，时间相同按商品编号升序，空发布时间排在末尾 |
| OQ-03 操作日志范围 | 北京时间日期。开始和结束日都包含，留空不设该端点，每页 20 条 |
| OQ-04 非公开详情 | 公开商品详情返回 404。卖家从自己的商品查看，预约当事人从对应预约查看交付和历史 |
| OQ-05 草稿 | 可以保存空草稿。用户显式保存，提交审核时检查完整性 |
| OQ-06 关键词 | 标题或描述内的大小写不敏感子串 |
| OQ-07 保留期 | 保留业务、操作结果和审计记录，应用无定期删除或清理入口 |

成交统计按北京时间左闭右开区间读取首次完成时间。金额用 PostgreSQL `NUMERIC` 和 Python `Decimal` 保存，输出为两位小数字符串。商品各状态当前数量独立统计。
